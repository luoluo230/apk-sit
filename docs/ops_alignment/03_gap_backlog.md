# 差距修复清单（P0/P1/P2）

更新时间：2026-06-01

## P0（必须修）
1. 动作中心动作目录与 game-server 动作类型的一一映射文档化并后端强校验（避免页面动作能选但 Agent 不支持）。
2. 诊断结果到动作执行的 trace_id/job_id 贯通与回执可追踪（诊断->修复闭环）。
3. 业务指标来源接入（qps/rtt_p95/rtt_p99/error_rate/conn），至少对 game/ops 节点提供真实值。

## P1（应修）
1. 事件与追踪统一主键规范（trace_id、job_id、node_id、agent_id）并前端联动跳转。
2. 变更治理从摘要页提升到可执行灰度/回滚编排（接 runtime flow-control 子策略）。
3. 合规策略下沉到动作粒度（高危动作模板级审批规则）。

## P2（优化）
1. 分布式回退策略可配置化（region->zone->project fallback）。
2. Agent 黑窗与 Web 增加同一采样时间戳对齐展示。
3. 补齐模块级自动化回归脚本（CI nightly smoke）。

## 最小改造路径
- 第一阶段：先补 P0，确保“可执行+可追踪+可解释”。
- 第二阶段：补 P1，让治理与追踪达到生产运维强度。
- 第三阶段：做 P2，提升弹性与可观测体验。
