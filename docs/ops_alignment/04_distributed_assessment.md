# 分布式部署评估（机房多节点优先）

更新时间：2026-06-01

## 现状
- Agent 注册/心跳已支持：`region/zone/rack/host_ip/device_id`（可选）。
- 绑定/启动主链路已可跑通：bind -> start-remote -> pull/report。
- 设备聚合与探测机制可支撑同机房管理。

## 可行性评估
- 单机与同机房：可用（当前已验证）。
- 多机房部署：可用但需策略补强（过滤/回退/失败清单标准化）。
- 跨区容灾：具备基础能力，缺少策略引擎与自动回退编排。

## 风险点
1. `metrics.business` 目前很多节点仍缺失，导致业务层判断不稳定。
2. 变更治理未形成实执行编排，跨区灰度与回滚只能半手工。
3. 动作模板与 Agent 动作能力映射仍需强约束，避免运行期拒绝。

## 建议默认策略
1. 节点启动优先同 `region`。
2. 同 region 不可达时回退同 `zone`。
3. 仍失败才允许同项目其他在线 Agent（需审批开关）。
4. 所有回退必须在结果清单写明命中路径与错误码。
