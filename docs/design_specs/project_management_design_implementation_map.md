## 页面壳层硬规则

- 左侧导航固定 232px，顶部栏固定 72px。
- 顶部项目控件是真实上下文下拉，只切换项目和环境。
- 顶部栏禁止出现创建项目、创建拓扑等业务操作。
- 页面主操作位于页面标题区右侧。
- 项目页面跳转必须保留 `env_key/channel_id/platform/version_name/version_code/release_order_id`。
- 加载、空、失败、无权限、处理中必须有独立可见反馈。

## 第一阶段交互与后端映射

| 可见操作 | 后端行为 | 反馈 |
|---|---|---|
| 切换项目/环境 | 更新 URL 上下文并保持当前模块 | 页面重新加载并显示新上下文 |
| 创建发布单 | 进入 P11 独立页面 | 不使用弹窗 |
| 保存草稿 | 创建或更新 `release_orders` | Toast + 保留编辑态 |
| 保存并进入构建 | 保存发布单并触发构建 | 跳转 P12，显示构建状态 |
| 执行预检 | 真实检查产物、拓扑、runtime、网络参数 | 阻断/警告/通过分组展示 |
| 审批、发布、验证、回滚 | 调用发布单状态机动作 | 页面时间线与下一步动作刷新 |

## 验收记录

第一阶段完成后必须逐页记录：

- 设计图与运行截图路径
- 壳层、标题区、主内容、右侧栏、文案、图标、交互的 PASS/FAIL
- 浏览器实际点击过的操作
- 实际加载的 CSS/JS cache 版本

## 全页面与弹窗截图门禁

- 必须逐页截图：项目总览、版本与 VersionCode、构建与产物、发布单中心、新建/编辑发布单、发布单详情、拓扑资产、拓扑绑定、拓扑画布、Agent 与服务器、运行执行、节点诊断、变更治理。
- 必须逐个截图所有可见弹窗、抽屉、确认框、下拉菜单、空状态、加载状态、失败状态与高风险状态。
- 有设计图的页面逐项对比布局、间距、字体、颜色、图标、边框、阴影、状态和文案；任何可见差异均为 FAIL。
- 无独立设计图的页面必须使用统一项目壳层、Token、组件、真实图片/SVG 图标和一致交互反馈；出现旧壳或第二套视觉语言即为 FAIL。
- 任何图标槽位禁止使用字符、Emoji、字体图标或文字模拟；优先使用设计师图标，缺失时补同风格 SVG。
- 每个截图验收必须同时验证页面可见操作具备真实后端效果，不允许只截图静态壳层。

## 最终生产验收硬门禁

以下三项必须同时通过，任意一项失败即视为项目管理模块未完成：

1. UI 无错乱：已有设计图页面严格按设计图还原，缺图页面严格遵循同一设计系统；无挤压、重叠、截断、旧壳残留和布局漂移。
2. 功能全部真实可用：每个可见按钮、筛选、标签、弹窗、抽屉和跳转均有真实业务效果；复杂流程使用独立页面，不错误嵌入其他模块；不存在装饰性假功能。
3. 全链路生产可用：版本、构建、产物、拓扑、runtime、预检、审批、发布、客户端 bootstrap、热更、登录、玩家数据、验证和回滚全部使用真实数据与真实服务打通；不存在只完成 UI 壳或返回假成功的环节。
