# 发版主线（人话流程）

配套计划：[`docs/architecture/plans/P1-06_release_flow_clarity.md`](../architecture/plans/P1-06_release_flow_clarity.md)

## 谁干什么

| 页面 | 职责 | 不是 |
|------|------|------|
| 发版中心 | 看线上 Runtime + 当前进度 + 下一步 | 不是执行台 |
| 发版（控制台） | 勾选交付线，构建 / 预检 / 发布 | 不是线上真值 |
| 构建与产物 | Jenkins 记录与制品下载 | 不是发布按钮 |
| 版本与管线 | 先选环境里的交付线，再看该平台大版本 / 该渠道构建 | 不是上线入口 |
| 发布历史 | 发布单列表与审批痕迹 | 不是主工作台 |

页面对外只保留这套名字：**发版中心 / 发版 / 构建与产物 / 版本与管线 / 发布历史**。旧称「版本管理」「版本代码」「发版控制台」不再出现在入口。

## 七步主线

1. **构建** — 出制品
2. **制品就绪** — 可追溯 APK / 热更 / 配置
3. **预检** — 兼容、产物、拓扑
4. **审批** — 生产按策略
5. **发布** — 激活 Bundle / 灰度
6. **验证** — 冒烟与启动校验
7. **线上生效** — 客户端实际加载的 active Bundle

内部仍用 `release_order.status`；页面只展示主线步骤，不把 17 种状态直接甩给用户。

## 两个真值

- **计划**：进行中的发布单（`release_order`）
- **线上**：当前环境 active Bundle（`runtime_snapshot`）

发版中心必须同时展示这两块，禁止只用「待发布版本」冒充线上。

## 版本与管线（交付线矩阵）

1. 先选环境（必选）。
2. 页顶矩阵 = 本环境的渠道 × 平台。格子只显示库存状态（线上 / 有构建 / 无该渠道构建 / 未配管线），不在这里发布。
3. 点一格：下面列出该 **环境+平台** 的版本组（管线），VersionCode 只显示该 **渠道**。
4. 「查看本环境全部」取消格子过滤，仍停留在当前环境。
