# Agent 管理中心与详情页设计实现文档

## 模块信息

- 模块名称：`Agent 管理中心` / `Agent 详情页`
- 页面路由：
  - `/admin/ops-platform/agent-control`
  - `/admin/ops-platform/agent-detail`
- 设计源：当前线程中的两张设计截图
- 设计资源预留：
  - `docs/design_assets/agent-center.png`
  - `docs/design_assets/agent-detail.png`

## 硬性目标

- 页面必须按设计图 1:1 实现，不接受“接近”或“风格类似”。
- 验收以浏览器运行态为准，不以源码或空态为准。
- 运行态不得出现乱码、混合编码、占位字符、旧壳残留、错误入口。
- 任何视觉差异未清零前，不得声称“已按设计图完成”。

## 设计拆解清单

### Agent 管理中心

- 左侧导航宽度、分组标题、激活态底色、图标、页脚折叠菜单
- 顶部面包屑、通知/帮助/头像区
- 标题、图标、说明文案
- 顶部三枚操作按钮：新建设备 Agent / 一键探测测试 / 批量修复并探测
- 四张 KPI 卡片：图标风格、数字字号、说明文案、圆角和阴影
- 筛选栏：状态、搜索、服务状态、活跃窗口、应用筛选、重置、视图切换
- 批量操作栏：已选择、批量探测、批量重启、批量绑定服务、更多操作、清理过期 Agent、自动刷新提示
- 主内容主态：双列 Agent 卡片，卡片信息与设计一致
- 分页器：位置、尺寸、激活态、每页条数选择器

### Agent 详情页

- 深色顶栏、左侧导航、面包屑
- 标题行：Agent 名称、状态、辅助图标、右上按钮组
- 元信息行：ID / 分组 / 环境 / 版本 / 最近心跳 / 安装时间
- Tab 栏：概览 / 设备信息 / 服务与进程 / 监控指标 / 任务历史 / 操作日志 / 配置管理 / 告警事件 / 审计日志
- 概览页五张摘要卡：状态、系统资源、连接信息、服务健康、告警事件
- 中部双栏：服务与进程表 + 监控图表
- 底部三栏：近期任务 / 告警事件 / 配置信息
- 底部系统信息栏

## 数据模型约束

- 页面语义必须是：`1 个 Agent -> 管理多个服务 / 游戏服务器`。
- Agent 列表与详情页都必须基于逻辑 Agent 聚合结果展示。
- 不允许把兼容层中的单服务记录直接当成最终 Agent 卡片。
- 实时资源卡、监控曲线、任务进度、运行状态等所有实时参数必须来自运行时采样或内存态，不允许直接读取落盘快照后伪装成实时。

## 本轮实现要求

- 本轮按“重写”执行，不在旧样式堆叠上继续补丁。
- 管理中心与详情页使用独立模板结构、独立样式命名空间、独立前端渲染逻辑。
- 保留真实路由与真实 API 接入，但前端允许做设计态视图模型归一化，以保证主态视觉与设计图一致。
- 重写受污染模板和脚本为干净 UTF-8。
- 管理中心与详情页都使用最新静态资源版本号，避免旧缓存命中。
- 改动后必须核对真实运行入口、服务进程和最终浏览器结果。

## 本轮补完范围

- 列表页彻底移除 `SHOWCASE_AGENTS` 假卡片，改为真实 `/api/ops-platform/agents` 逻辑 Agent 聚合结果渲染。
- 列表页 CPU / MEM / DISK 仅显示真实 `metrics.control` 或 `device_metrics_snapshot.control`，缺值显示 `--`。
- 列表页 Agent 卡右侧增加“管理服务器”列表，仅显示 `server/service id + 状态`，用于减少卡片大留白。
- 列表页每张 Agent 卡右上角三点菜单补齐：查看详情、立即探测、重启 Agent、编辑 Agent、查看日志。
- 详情页“服务与进程”模块补齐真实服务实例操作：启动、停止、重启、编辑、查看状态、查看日志。
- 详情页服务操作必须具备二次确认弹窗：启动、停止、重启、删除服务器。
- 详情页服务表头补齐 `新增服务器` / `删除服务器`，新增走 `/api/ops-platform/services/upsert`，删除走新增的 `/api/ops-platform/services/delete`。
- 删除语义固定为真删 Agent `services[]` 中的正式实例；兼容聚合服务必须显式阻断并返回明确信息。

## 本轮设计分析补充

### 实时参数与图表约束

- 详情页系统资源卡中的 CPU / 内存 / 磁盘必须使用 Agent 实时采样值，不允许使用落盘恢复值冒充实时。
- 监控图表只能渲染真实历史采样点；没有至少 2 个真实点时，显示无历史采样态，不允许重复单点伪造平线。
- 详情页需要定时刷新以体现实时采样，但刷新来源必须是运行时内存态或实时上报链路，而不是反复读取持久化快照。

### 逻辑 Agent 聚合与拓扑关系

- 需要区分 `cluster.json` 兼容聚合条目与运行时自注册 Agent。
- `local-game-server` 代表 cluster 兼容聚合组；`local-gateway` 这类独立运行时 Agent 必须明确标识为独立 Agent，而不是与 cluster 兼容组混淆。
- 如果同一 `node_id / service_id` 同时出现在运行时自注册和兼容聚合条目中，聚合层必须明确优先级并识别重复/脏注册，不能让页面同时把它们都当成正常主态。

### 页面壳与宽度

- 列表页为浅色独立壳：左侧白底导航宽度固定，右侧内容区铺满，顶部工具栏高度固定。
- 详情页为深色顶栏 + 白色内容壳：顶栏单独成层，内容区最大宽度按设计留白，不复用列表页顶部结构。
- 两页都必须在 1440px 以上保持和设计相同的水平密度，在 1280px 左右仍不出现错列与挤压。

### 导航与激活态

- 列表页左侧导航激活项为浅蓝底 + 蓝色文字 + 蓝色图标底。
- 详情页左侧导航更紧凑，激活项使用更细长的高亮条和浅蓝底。
- 分组标题、分隔线、页脚折叠入口位置必须与设计一致。

### 标题区与按钮组

- 列表页标题区：左侧标题图标、主标题、副标题；右侧三按钮尺寸、高度、圆角、描边完全对齐。
- 详情页标题区：Agent 名称、状态胶囊、辅助跳转图标、右上按钮组对齐到同一基线。
- 主按钮与次按钮必须使用不同视觉层级，不允许退化成统一按钮样式。

### KPI / 摘要卡

- 列表页 4 张 KPI 卡需保持相同高度、圆角、边框、轻阴影与图标圆底。
- 详情页 5 张摘要卡需保持横向等宽；卡内标题、主数值、辅助说明按设计分层。
- 资源类卡片中的百分比、服务数、告警数都使用等宽数字感的对齐方式。

### 筛选区 / 批量工具条 / 视图切换

- 筛选区是一整行胶囊化控件，不得出现不齐的控件高度或搜索框错位。
- 批量工具条需要左操作组、右说明组双端对齐。
- 卡片视图 / 列表视图切换按钮必须呈现明确的选中底与描边。

### 列表主态

- 主态按双列卡片排布，每张卡片含：选择框、设备图标、标题、状态胶囊、IP、最后心跳、三枚资源指标、服务摘要、三枚底部操作按钮、右上更多按钮。
- 选中态使用蓝描边与淡蓝外发光；异常态使用橙描边；离线态使用红状态色。
- 分页器需包含总数、左右翻页、当前页、页大小选择器，排列顺序按设计。

### 详情主态

- Tab 栏默认概览态，使用细下划线高亮，间距紧凑。
- 中部双栏为“服务与进程表 + 监控图表”，下部三栏为“近期任务 + 告警事件 + 配置信息”。
- 图表是细折线 + 轻网格，不使用厚重卡片图表样式。

### 状态与异常态

- 空态、加载态、错误态均放在卡片或主面板内部，不破坏页面整体壳结构。
- Hover、active、disabled、selected 需要和设计语言统一：蓝色高亮、浅描边、轻阴影，不使用默认浏览器态。
