# Agent 管控中心与详情页设计实现说明

## 模块信息

- 模块名称：Agent 管控中心 / Agent 详情页
- 页面路由：
  - `/admin/ops-platform/agent-control`
  - `/admin/ops-platform/agent-detail`
- 设计图来源：用户在 Codex 线程中提供的 Agent 中心与详情页设计截图
- 推荐本地设计图文件：
  - `docs/design_assets/agent-center.png`
  - `docs/design_assets/agent-detail.png`

## 设计图硬性要求

- 实现必须尽量按设计图 1:1。
- 布局、层级、按钮尺寸、卡片密度、筛选栏、分页、标签页、表格、空态都必须按设计图落地。
- 页面必须是全宽控制台布局，不能出现意外居中、右偏、横向溢出。
- 与设计图冲突的旧壳和旧结构必须移除，而不是半保留。
- 本模块视觉验收默认以“有数据主态”为准，不能只用空态页面作为完成依据。

## 当前已暴露的视觉偏差重点

### Agent 管控中心

- 当前实现截图主态为“空列表”，而设计图主态为“双列 Agent 卡片列表”，这属于阻塞级差异。
- 顶部主按钮区缺少与设计图一致的图标风格，目前仍偏向文本按钮。
- KPI 卡片图标风格、颜色层次、数字内容与设计图不一致；不能只对齐容器尺寸。
- 左侧导航的图标系统、分组留白、激活态高亮仍与设计图有差异。
- 筛选栏虽然结构接近，但控件图标、内边距、按钮细节仍需继续按图对齐。
- 批量操作栏与分页栏需要在“有数据主态”下继续核对，不能只在空态下判断。

### Agent 详情页

- 必须在真实或可控演示数据下核对五张摘要卡、服务表、图表、底部三栏，而不是只看骨架。
- 顶部深色栏、标题区、tab、摘要卡、图表和表格都要按截图逐项比对。
- 图标风格必须统一，不能混用占位字符、emoji 和正式 UI 图标风格。

## Agent 管控中心

### 页面结构

- 左侧导航
- 顶部工具栏
- 面包屑
- 页面标题与副标题
- 顶部主操作按钮组
- 四个 KPI 概览卡
- 筛选工具栏
- 批量操作栏
- 双列 Agent 卡片区
- 底部分页栏

### 视觉要求

- 左侧导航宽度固定，并与设计图对齐。
- KPI 卡片使用浅边框、轻阴影、大圆角、左侧图标块。
- 筛选控件在宽屏下一行对齐，在较窄宽度下自然换行。
- Agent 卡片必须展示：
  - 勾选框
  - 设备图标
  - 设备 / Agent 标题
  - 状态标签
  - IP
  - 最后心跳
  - CPU / MEM / DISK 指标胶囊
  - 服务摘要
  - 底部操作按钮

### 功能要求

- 按状态筛选
- 按关键字搜索
- 按服务状态筛选
- 按活跃时间窗口筛选
- 卡片 / 列表视图切换
- 批量选择
- 批量探测
- 批量重启服务
- 批量绑定服务入口
- 清理过期 Agent
- 单卡片支持：
  - 查看详情
  - 编辑
  - 探测

## Agent 详情页

### 页面结构

- 左侧导航
- 深色顶部栏
- 面包屑
- 标题行与状态
- 元信息行
- 顶部操作按钮
- 标签页栏
- 五个摘要信息卡
- 中部双栏区域：
  - 服务 / 进程表
  - 监控图表
- 底部三栏区域：
  - 近期任务
  - 告警事件
  - 配置摘要
- 底部系统信息栏

### 视觉要求

- 顶部五张信息卡高度一致。
- 标签页横向对齐，激活态为细下划线样式。
- 表格使用稳定列宽，数字列对齐。
- 监控图块的密度、间距、留白要贴近设计图。

### 功能要求

- 概览页必须优先完整可用。
- 设备信息、服务与进程、监控指标、任务历史、操作日志、配置管理、告警事件、审计日志使用统一数据契约。
- 顶部操作至少包含：
  - 编辑
  - 重启 Agent
  - 更多操作

## 代码架构要求

- 模板、样式、脚本按页面职责拆分。
- 避免单个大脚本承载全部页面逻辑。
- 为贴合设计图而重写模块时，移除已废弃逻辑。
- 不保留“也许以后要兼容”的旧 UI 分支，除非用户明确要求。

## 验证清单

- 变更后的 JS 无语法错误
- 变更后的 Python 无编译错误
- 变更文件无乱码
- 页面无横向溢出
- 页面未命中旧壳 / 旧模板 / 旧服务实例
- 左侧导航、顶部工具栏、筛选区、卡片、表格、标签页、分页与设计图尽量一致
