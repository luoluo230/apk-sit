## 0. 文档使用规则

### 0.1 唯一真源

本文件是新项目管理模块的唯一产品设计真源。设计师应根据本文件输出整套页面、组件、弹窗、抽屉、交互原型和视觉规范。

以下内容只能用于了解已有业务能力，不得作为新页面布局依据：

- 当前运行中的项目管理页面。
- 旧 GM 发版工作台。
- 旧运维平台页面。
- 旧项目版本管理设计图。
- 旧拓扑工作台外层布局。
- 旧页面中的顶部操作按钮、侧栏结构和弹窗结构。

新设计不要求兼容旧页面结构。旧逻辑与本文件冲突时，以本文件为准。

### 0.2 设计完整性要求

设计师必须交付：

- 全部页面的正常态设计。
- 全部关键页面的空状态、加载状态、失败状态和无权限状态。
- 全部业务弹窗、确认弹窗和抽屉。
- 页面之间的交互跳转原型。
- 字体、字号、颜色、间距、圆角、阴影、图标、状态色等设计规范。
- 桌面端基准稿和关键窄屏适配稿。

不得只输出首页和几个核心页面后，让开发自行推导其余页面。

## 1. 产品定位

### 1.1 产品目标

项目管理是以“一个游戏项目从开发到正式运行”为核心的交付与运行管理产品。

用户必须能够在同一个项目工作区完成：

```text
查看项目状态
→ 维护版本与 VersionCode
→ 创建发布单
→ 触发构建并确认产物
→ 选择和验证运行拓扑
→ 完成预检与审批
→ 发布并验证客户端链路
→ 管理服务器运行态
→ 诊断、变更与回滚
→ 查询完整审计记录
```

### 1.2 产品主实体

| 实体 | 含义 | 与其他实体的关系 |
|---|---|---|
| 项目 Project | 所有交付和运行资产的归属主体 | 拥有环境、渠道、版本、拓扑、服务器和发布单 |
| 环境 Environment | 开发、测试、预发、生产等运行隔离空间 | 每个环境有独立版本、拓扑、服务器和发布状态 |
| 渠道 Channel | 微信、抖音、华为、官方包等业务渠道 | 与环境、平台、版本共同确定发布目标 |
| 平台 Platform | Android、iOS 等客户端平台 | 与渠道和 VersionCode 共同确定产物 |
| 版本组 Version Group | 对外展示的大版本，如 v1.2.4 | 包含多个 VersionCode |
| VersionCode | 可构建、可测试、可发布的精确客户端版本 | 关联构建、产物和发布单 |
| 发布单 Release Order | 一次完整交付计划和执行记录 | 串联版本、构建、产物、拓扑、审批、发布和验证 |
| 构建任务 Build | Jenkins/Unity 的一次构建执行 | 必须关联 VersionCode 和发布单 |
| 产物 Artifact | 资源、配置、代码、APK/IPA 等交付文件 | 来自构建任务，被发布单选用 |
| 拓扑资产 Topology | 项目可复用的服务节点与连接结构 | 通过绑定规则命中发布目标 |
| 运行实例 Runtime | 某拓扑在某环境中的真实运行状态 | 发布前必须就绪，发布后用于验证 |
| Bundle | 发布单产生的不可变运行快照 | 冻结版本、产物、拓扑、网络和服务端快照 |
| Agent/服务器 | 实际承载服务进程的机器和 Agent | 属于项目环境，被拓扑节点引用 |
| 审批 Approval | 对生产发布或高风险动作的授权记录 | 必须关联发布单或变更动作 |
| 变更/动作 Change/Action | 启停、重启、升级、流控等运维操作 | 必须关联项目、环境和影响对象 |

### 1.3 主业务链路

```text
项目总览环境卡
→ 创建发布单
→ 编辑交付计划
→ 选择 VersionCode
→ 触发或选择构建
→ 校验全部产物
→ 解析并确认拓扑
→ 检查 Runtime/Agent/服务器
→ 执行预检
→ 生产审批
→ 发布生成 Bundle
→ runtime-bootstrap 客户端验证
→ 登录与玩家数据验证
→ 完成或回滚
```

### 1.4 产品范围边界

#### 属于本项目管理产品

- 项目总览与环境运营。
- 项目成员、角色和权限。
- 项目协作任务。
- 项目文档与交付知识。
- 版本、VersionCode、构建、产物、下载和测试设备。
- 发布单、预检、审批、发布、验证和回滚。
- 项目拓扑、绑定、Runtime、Agent、服务器、动作和诊断。
- 项目变更治理和审计日志。
- 项目内 Jenkins、Unity、OSS/CDN、通知等集成配置。

#### 不属于本项目管理产品

- 平台级 Jenkins 实例安装、升级和删除。
- 平台级 Unity 版本目录维护。
- 平台级用户、角色模板和系统设置。
- 官网产品展示、玩家下载门户和玩家社区内容运营。
- 跨项目经营分析和平台容量治理。

以上平台级能力可以从项目设置提供关联状态和跳转入口，但不得直接混入项目工作区页面。

## 2. 用户角色与权限体验

| 角色 | 主要目标 | 默认可见能力 | 高风险限制 |
|---|---|---|---|
| 项目负责人 | 查看项目整体交付与运行状态 | 全项目总览、发布单、版本、构建、拓扑摘要 | 生产发布需审批 |
| 版本管理员 | 管理版本、VersionCode、渠道与产物 | 版本、构建、发布单草稿 | 不直接操作生产服务器 |
| 构建工程师 | 管理 Jenkins 构建与产物 | 构建中心、构建日志、产物 | 不直接发布生产 |
| 运维工程师 | 管理拓扑、Agent、服务器和动作 | 运行环境、拓扑、诊断、动作执行 | 高风险动作需审批 |
| 发布审批人 | 审查生产发布和高风险动作 | 审批详情、差异、风险和历史 | 不得审批自己提交的生产发布 |
| 测试人员 | 安装测试包并完成验证 | 测试设备、下载、发布验证 | 不可修改发布计划 |
| 审计人员 | 查询全部操作与变化 | 审计日志、审批、发布记录 | 只读 |

设计要求：

- 无权限时不只隐藏按钮，还要提供“为何不可用”的提示。
- 高风险动作必须展示影响范围、风险等级、审批要求和回滚方案。
- 同一页面可因权限不同呈现只读态、可编辑态和审批态。

## 3. 统一项目上下文

### 3.1 上下文层级

```text
项目 project_id
└─ 环境 env_key
   └─ 渠道 channel_id
      └─ 平台 platform
         └─ 大版本 version_name
            └─ VersionCode version_code
               └─ 发布单 release_order_id
```

### 3.2 页面允许的上下文粒度

| 页面类型 | 允许“全部” | 必须精确 |
|---|---|---|
| 项目列表 | 项目可全部 | 无 |
| 项目总览 | 环境、渠道、平台可全部 | 项目 |
| 版本管理 | 环境、渠道、平台、版本可全部 | 项目 |
| 构建历史 | 环境、渠道、平台、版本可全部 | 项目 |
| 发布单中心 | 状态、环境、渠道、平台可全部 | 项目 |
| 新建发布单 | 不允许全部 | 项目、环境、渠道、平台、VersionCode |
| 发布单详情 | 不允许全部 | 发布单 |
| 拓扑资产 | 环境、状态可全部 | 项目 |
| 拓扑绑定 | 渠道、版本筛选可全部 | 项目 |
| 运行工作台 | 不允许全部 | 项目、环境 |
| 动作执行 | 不允许全部 | 项目、环境、动作目标 |

### 3.3 上下文切换交互

- 顶部项目选择器必须是真实下拉，不得伪装成下拉的跳转链接。
- 项目切换后清除旧项目的环境、版本、发布单等下级上下文。
- 环境切换后保留仍合法的渠道和平台，不合法的值自动清除并提示。
- 执行构建、预检、发布、回滚、运维动作前必须显示完整精确上下文。
- 生产环境使用独立醒目标识，不允许仅依赖文字区分。

### 3.4 顶部栏职责

顶部栏只允许包含：

- 侧栏展开/收起。
- 面包屑。
- 项目选择器。
- 全局搜索。
- 帮助。
- 通知。
- 用户菜单。

顶部栏禁止出现：

- 创建项目。
- 新建拓扑。
- 创建版本。
- 创建发布单。
- 发版、回滚、服务器启停等业务动作。

业务创建和执行动作必须放在所属页面的标题区或内容区。

## 5. 全局设计系统要求

### 5.1 设计 Token

设计师必须提供：

- 字体家族和 Web 可用回退字体。
- 标题、正文、辅助文字、表头、标签、数字的字号、字重和行高。
- 主色、辅助色、中性色、背景色、边框色。
- 成功、处理中、警告、失败、阻断、未配置、禁用状态色。
- 4/8 基础间距体系或其他明确间距体系。
- 卡片、按钮、弹窗、抽屉的圆角和阴影。
- 左侧栏、顶部栏、内容区、右侧辅助栏的尺寸规范。
- 桌面端基准宽度和响应式断点。

### 5.2 语义状态色

| 状态语义 | 使用场景 | 推荐方向 |
|---|---|---|
| 正常/成功 | 运行正常、预检通过、发布成功 | 绿色 |
| 处理中 | 构建中、发布中、验证中 | 蓝色 |
| 待处理/待审批 | 等待审批、需人工确认 | 橙色 |
| 风险/阻断/失败 | 预检失败、离线、发布失败 | 红色 |
| 未配置/无数据 | 无版本、未绑定、未运行 | 灰色 |
| 草稿 | 未提交计划、拓扑草稿 | 中性灰或浅蓝 |

### 5.3 通用组件

设计师需提供完整组件态：

- 主要、次要、文字、危险、禁用、加载按钮。
- 输入框、搜索框、下拉、级联选择、单选、多选、日期时间、文本域。
- Tab、步骤条、面包屑、分页、筛选器、批量操作栏。
- KPI 卡、环境卡、状态卡、阻断卡、发布单卡、版本卡、拓扑卡。
- 表格、树表、时间线、日志查看器、代码/JSON 查看器。
- 状态标签、风险标签、数字徽标、来源标签。
- Toast、行内提示、全页错误、空状态、加载骨架、无权限。
- 弹窗、抽屉、Popover、Tooltip、危险确认框。

### 5.4 图标与切图

必须提供：

- 全部导航图标。
- 项目、环境、渠道、平台、版本、构建、产物、发布、拓扑、Agent、服务器、审批、诊断、日志图标。
- 成功、处理中、警告、失败、阻断、未配置状态图标。
- 空项目、无版本、无构建、无发布单、未绑定拓扑、服务器离线、无权限插图。
- SVG 优先；位图提供透明背景的 1x/2x。
- 图标命名、尺寸、默认色、激活色、禁用色和使用场景表。

## 7. 页面详细需求

## P01 项目列表

### 页面目标

查看有权限的项目、项目健康摘要并进入项目工作区。

### 页面布局

- 标题区：项目管理、项目数量、创建项目按钮。
- 筛选区：搜索、状态、负责人、健康状态。
- 主内容：项目卡片或表格，允许设计师选择一种主视图。
- 项目卡必须展示：项目名称、图标、负责人、环境健康、当前生产版本、待审批、阻断项、最近发布。

### 真实操作

- 创建项目。
- 进入项目总览。
- 编辑项目基础信息。
- 归档项目。
- 查看项目成员。

### 必须设计状态

- 有多个项目。
- 无项目。
- 筛选无结果。
- 项目健康。
- 项目存在阻断。
- 项目归档。
- 无创建权限。

---

## P02 项目总览

### 页面目标

成为项目交付与运行的统一入口，让用户立即知道每个环境当前状态、阻断原因和下一步操作。

### 页面布局

- 项目标题区：项目名称、整体健康、负责人、最近更新时间。
- 项目 KPI：环境健康数、进行中发布单、待审批、阻断项、在线服务器。
- 四张环境卡：开发、测试、预发、生产。
- 最近活动：最近构建、最近发布、运维异常、审批。
- 右侧辅助区可展示项目成员、快捷帮助，但不得堆叠业务创建按钮。

### 环境卡字段

- 环境名称和健康状态。
- 当前 active Bundle。
- 当前版本组和 VersionCode。
- 当前命中拓扑及运行状态。
- 渠道数、平台数。
- 进行中发布单。
- 待审批发布单。
- 阻断项数量和最高风险。
- 最近构建与最近发布时间。

### 环境卡操作

- 创建发布单。
- 继续进行中的发布单。
- 查看阻断项。
- 进入环境详情。
- 查看拓扑。
- 进入运行工作台。

### 必须设计状态

- 正常运行。
- 未配置。
- 有发布单执行中。
- 待审批。
- 存在阻断。
- 服务离线。
- 发布成功但验证失败。

## P03 环境详情

### 页面目标

聚合一个环境下所有渠道、平台、版本、拓扑和服务器状态。

### 页面模块

- 环境健康摘要。
- 渠道/平台矩阵。
- 当前生效版本与 Bundle。
- 当前拓扑绑定和运行实例。
- 服务器与 Agent 摘要。
- 进行中和最近发布单。
- 阻断项与诊断建议。
- 最近变更和操作日志。

### 页面操作

- 创建发布单。
- 查看当前 Bundle。
- 查看拓扑绑定。
- 进入运行工作台。
- 执行诊断。

## P04 版本与 VersionCode

### 页面目标

管理版本组和 VersionCode，并从精确版本创建发布单或构建任务。

### 页面模块

- KPI：版本组数、有效 VersionCode、构建中、产物完整、已发布。

### 计划分区

   - 立即发布或计划时间。

   - 自动回滚条件。
   - 人工回滚负责人。

- 复制计划。
- 取消。

## 9. 全局反馈与异常状态

每个页面设计稿必须根据适用范围覆盖以下状态：

### 9.1 页面级

- 首次加载骨架。
- 加载失败，可重试。
- 无权限。
- 对象不存在或已删除。
- 空状态，并提供下一步操作。
- 筛选无结果。

### 9.2 表单级

- 初始状态。
- 必填缺失。
- 格式错误。
- 字段冲突。
- 保存中。
- 保存成功。
- 保存失败。
- 数据已被其他用户修改。
- 当前状态不允许修改。

### 9.3 执行级

- 等待执行。
- 排队。
- 执行中和真实进度。
- 成功。
- 部分成功。
- 失败并允许重试。
- 失败且必须人工处理。
- 已取消。
- 网络断开后恢复。
- 重复提交被拦截。

### 9.4 高风险操作

- 生产环境标识。
- 风险等级。
- 影响对象。
- 是否需要审批。
- 回滚方案。
- 输入确认文字。
- 执行后不可逆提示。

## 14. 架构硬规则与潜在失败场景

本章不仅约束开发，也约束产品和设计。设计稿必须能够表达这些业务规则及异常反馈。

### 14.1 项目与上下文硬规则

1. 项目是所有版本、构建、发布、拓扑、服务器、审批和日志的唯一归属主体。
2. 所有项目内页面 URL 必须带 `project_id`。
3. 所有执行类动作必须拥有精确环境，不允许在“全部环境”下执行。
4. 渠道在 UI 展示业务名称，数据层使用稳定的 `channel_id`。
5. 项目切换后必须清空旧项目的发布单、版本、拓扑和环境上下文。
6. 环境切换后必须重新验证渠道、平台、版本和拓扑是否合法。
7. 页面刷新、浏览器返回、分享链接后，页面数据和上下文选择器必须一致。
8. 生产环境必须在标题、按钮确认和执行反馈中持续显示生产标识。
9. 上下文不完整时，页面必须明确提示缺少什么，不得静默使用默认生产环境。
10. 当前对象已删除、已归档或无权限时，必须阻止继续执行并提供返回入口。

### 14.2 发布单硬规则

1. 发布单是一切交付动作的主实体，不是点击发布时临时生成的记录。
2. 一张发布单固定对应一个项目、环境、渠道、平台和 VersionCode。
3. 发布单必须包含交付计划和执行记录两部分。
4. 草稿阶段允许编辑，进入预检后影响发布内容的字段必须锁定。
5. 修改版本、构建、产物、拓扑、发布策略或验证方案后，旧预检和审批必须失效。
6. 生产发布必须审批，且提交人不得审批自己的发布单。
7. 发布单必须明确当前下一步、阻断原因和可执行动作。
8. 发布单取消后不得继续构建、预检、审批或发布。
9. 发布中页面刷新或网络断开后，必须恢复真实执行状态，不得重复提交。
10. 发布成功但验证失败必须作为独立严重状态展示，不得显示为普通成功。
11. 回滚必须恢复旧 Bundle 的版本、产物、拓扑、网络和服务快照。
12. 每次状态变化必须记录操作者、时间、前状态、后状态和原因。
13. 同一目标存在并行发布单时必须提示覆盖和乱序风险。
14. 发布接口必须幂等，重复点击不得生成多个 Bundle。

### 14.3 版本、构建与产物硬规则

1. VersionCode 是可构建和可发布的精确版本，版本组不能直接发布。
2. 每次构建必须关联项目、环境、渠道、平台、VersionCode 和发布单。
3. 构建列表必须展示全量历史并支持分页，不得只展示最近有限记录。
4. 构建重试必须创建新构建记录，不得覆盖原失败记录。
5. Jenkins 延迟回调不得覆盖更新构建任务的状态。
6. 构建成功不代表产物完整，资源、配置、代码和安装包必须分别校验。
7. 产物必须记录来源构建、大小、校验值、路径和 OSS 可达性。
8. 发布单必须明确选择当前采用的构建批次。
9. 重新构建后不得静默替换发布单已经选定的产物。
10. 被发布单或 Bundle 引用的构建和产物禁止直接删除。
11. 手工替换产物必须产生审计记录，并使旧预检失效。
12. 页面必须区分“构建失败”“构建成功但产物缺失”“产物不可达”。

### 14.4 拓扑与运行态硬规则

1. 拓扑资产、拓扑绑定、运行实例和 Bundle 拓扑快照是四种不同对象。
2. 修改拓扑资产不得自动改变已发布 Bundle。
3. 发布单必须解析并冻结最终命中的拓扑和绑定来源。
4. 绑定优先级固定为：项目默认、环境/渠道覆盖、大版本覆盖。
5. 绑定矩阵必须解释当前命中的来源，不得只显示拓扑 ID。
6. 绑定冲突、未绑定、拓扑不可用时必须阻止发布。
7. 拓扑命中不代表 Runtime 就绪，必须单独检查真实运行实例。
8. Runtime 与拓扑结构漂移时必须阻止发布并显示差异。
9. Agent、服务器和服务进程必须能够反查所属项目、环境和拓扑节点。
10. 运维动作必须记录影响的发布单、Bundle 和运行实例。
11. 修改影响当前生效 scope 的绑定后，必须提示需要重新发布。
12. 已被 Bundle 或运行实例引用的拓扑禁止直接删除。

### 14.5 审批、权限与审计硬规则

1. 权限至少按项目、环境、动作类型分级。
2. 查看权限不等于构建、发布、审批或运维执行权限。
3. 审批详情必须展示计划、差异、风险、产物、拓扑和回滚方案。
4. 审批完成后计划发生变化，审批自动失效。
5. 高风险运维动作和生产发布必须有独立确认与审批反馈。
6. 审计日志必须记录对象、上下文、前后值、操作者、时间和结果。
7. 删除、归档、覆盖、回滚等高风险操作必须展示引用关系和影响范围。
8. 无权限按钮不得只消失；需要在适当位置解释权限限制。

### 14.6 UI 与交互硬规则

1. 同一产品只能有一套项目壳层、一套导航和一套上下文交互。
2. 顶部栏不得成为业务按钮集合。
3. 总览页用于发现问题和进入流程，不得承载所有编辑表单。
4. 复杂流程必须使用独立页面，不得塞入超大弹窗。
5. 弹窗关闭后可能丢失大量输入时，必须提供未保存提示。
6. 每个空状态必须解释原因并提供下一步操作。
7. 加载失败、无数据、无权限和未配置必须使用不同反馈。
8. 同一状态在所有页面使用相同中文名称、颜色和图标。
9. 页面显示的每个可点击控件都必须有真实功能。
10. 实时进度和运行状态必须来自真实运行数据，不得使用假进度。
11. 列表必须考虑长文本、超多记录、分页、筛选和批量操作。
12. 页面不得因为右侧栏、附加卡片或弹窗挤压主工作区。
13. 拓扑画布等专业工作区可以使用独立沉浸式布局，但视觉规范必须统一。
14. 删除和危险操作不得使用浏览器原生 `alert/confirm/prompt`。

### 14.7 必须在设计稿中体现的潜在失败场景

| 场景 | 页面必须如何反馈 |
|---|---|
| 切换项目后原发布单不属于新项目 | 清理旧上下文并提示已切换项目 |
| 环境没有渠道或版本 | 展示配置入口，不显示空下拉 |
| 发布单修改后预检失效 | 显示失效原因和重新预检按钮 |
| 构建成功但 OSS 文件不可达 | 产物卡红色阻断，并提供重试校验 |
| 拓扑绑定变更影响已发布环境 | 展示影响 Bundle 和重新发布提示 |
| Runtime 未运行 | 发布单阻断，并跳转环境运行工作台 |
| 生产审批后计划又被修改 | 审批失效，需重新提交 |
| 发布请求重复提交 | 保持原任务进度，不创建重复任务 |
| 发布成功但客户端登录失败 | 显示“已发布/验证失败”，提供回滚与诊断 |
| 回滚目标 Bundle 不可用 | 阻止回滚，展示缺失快照或产物 |
| Agent 心跳过期 | 明确显示离线时间、影响服务和处理入口 |
| 用户没有生产发布权限 | 保留只读信息，说明所需角色 |
| 对象正在被其他用户编辑 | 提示数据已变化并允许刷新比较 |
| 页面接口部分失败 | 保留可用区域，并在失败模块局部重试 |

## 15. 本 PRD 的交付验收标准

设计师交付整套设计后，必须能够仅凭设计源文件和本 PRD 回答：

- 用户从哪里创建项目。
- 用户如何真实切换项目和环境。
- 用户从哪里创建、编辑和继续发布单。
- 发布单每个阶段显示什么、允许做什么、失败后如何恢复。
- 用户如何查看全部构建记录和全部产物。
- 用户如何判断构建成功但产物不完整。
- 用户如何查看拓扑资产、绑定规则、运行实例和 Bundle 快照的区别。
- 用户如何从发布阻断跳转到服务器或拓扑问题处理页面。
- 生产发布如何审批、执行、验证和回滚。
- 每一个页面、弹窗、抽屉的正常、空、加载、失败和无权限状态如何展示。
- 所有图标、字体、字号、颜色、间距、状态和组件如何统一使用。

任一问题无法从设计稿和本 PRD 中得到明确答案，均视为设计交付不完整。
