# 版本组发版管线（客户端收敛）

| 项 | 值 |
|---|---|
| 主入口 | `/admin/projects/{project_id}/versions?env_key=&channel_id=&platform=` |
| 设计源 | `docs/design_assets/version_group_pipeline/hand_sketch_pipeline.png` |
| 对比现状 | `docs/design_assets/version_group_pipeline/current_versions_page.png` |
| 粒度 | **一行 = 一个版本组**；客户端发版主路径收敛到本轨 |

## 产品目标

把「版本表 + 多入口按钮」改为 **状态机主视图**：用户一眼看到当前卡在哪一步、下一步点什么。

## 四步模型（定稿）

| # | id | 文案 | 完成条件 | 节点点击进入 |
|---|----|------|----------|--------------|
| 1 | prepare | 准备 | 管线四步配置完整 + Jenkins 实例/Job + **构建节点在线** + 交付线有 VC + 发版必填项齐全 | 配置管线 / 发版编辑（不合规项标红） |
| 2 | build | 打包 | 准备已通过，且 Jenkins 完整构建成功并有可测产物（构建中=进行中；失败=红） | 构建流程（打包机进度与步骤） |
| 3 | verify | 验收 | 打包已完成，且 `client_acceptance=passed`（已发布视为通过；不通过=红） | 产物验收弹层 |
| 4 | release | 上线 | 验收已通过，且活跃 Bundle / 已发布 | 上线信息（发版编辑） |

- **硬门禁**：上一步非 `success` 时，下一步保持 `pending/未解锁`，不可进入
- 准备不合规显示 **红色「待修正」**；点开后标红必填未填与阻断项
- 已有进度的节点（失败/进行中/已完成）可回看；纯未解锁节点不可点
- Jenkins 子阶段不在主轨展开，进入「打包」节点后查看
- 「本交付线 VersionCode」可折叠
- 左侧「客户端」竖排正向（`vertical-rl` + `text-orientation: upright`）

## 卡片结构（对照手绘）

```
┌ 客户端 ┐  版本组 1.0.0                    [配置管线] [发版记录] [产物]
│        │  准备 → 打包 → 验收 → 上线
│        │  [当前步主按钮]
└────────┘                                         [删除]
```

- 左侧竖标：`客户端`（后续可扩展服务端轨，本期不做）
- 轨内仅前进箭头；次要入口收在右上
- VersionCode 默认折叠在「打包」详情区，不铺嵌套大表

## 页面收敛

| 保留 | 降级/移除出主视线 |
|------|-------------------|
| 环境 × 渠道 × 平台筛选（交付线） | 版本组表格头 + 行内并列操作堆 |
| 新建版本组 / 创建版本 | 「构建流程」「发版流程」双入口并列抢主路径 |
| 四步管线卡列表 | 复杂就绪条文案（管线✓产物✗…） |

## 文案清单

- 步骤：准备、打包、验收、上线
- 角入口：配置管线、发版记录、产物
- 危险：删除
- 空态：当前交付线还没有版本组。请先新建版本组。

## 验收主态

1. 有版本组 + 管线就绪 + 有 VC + 部分失败构建（展示 failed / 当前步）
2. 空态（无版本组）
3. 未选渠道时提示先选交付线（可选）

## 与旧 journey 关系

- `build_journey_channel` / `release_journey_channel` 降为**步骤详情页**
- 本页为客户端发版**唯一主入口**
